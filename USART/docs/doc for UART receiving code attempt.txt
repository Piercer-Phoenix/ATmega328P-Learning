Purpose of the code: To write a code which will read the USART peripheral's receiver and then use the received data as a command to activate any one of the 2 LEDs, based on the data sent. 
This is a beginner UART receiving implementation using the USART peripheral, in the ATmega328P.




A little mental model of the USART asynchronous receiving mode:
-> The USART receiving device supports parity checking, stop bit checking, sample clock generation (which both tx and rx use).

-> The USART receiving device has many more features like the receiver error flags, parity checker, and etc. The point is, I'll only be focusing on the things my scope is limiting me to, which is, just receiving frames, sampling bits and output a byte. 

-> A summary of The UART protocol would be helpful before reading the corresponding code and the architecture below. 

-> UART is a simple protocol which facilitates asynchronous communication (no clock is involved in the communication. Though, timers are used on the individual devices.) There is a rate of communication which is agreed by both the devices before the communication begins.

-> The baud rate is the number of bits transmitted/received in one second. The baud rate is managed by the clock signal which is generated by the USART based on the values of the UBRRn register values. The UBRR value allows us to generate a similar baud rate on devices running on different master clock frequencies, as We can increase the divisor value if the clock freq is higher. 

*) The baud rate formula is as follows : Baud rate = (master clock freq) / (16 * (ubrr + 1)) , and ubrrn value calculation formula is as follows:

ubrrn = ((master clock freq) / ((16 * baud rate)) - 1)


A little theory on the receiver: 


-> The UART tx or rx line is always held high, ie, idle -> high. So start bit is a low signal, and each bit lasts for 16 sample clock signals, which depends on the baud rate. The sample clock frequency is ( baud rate * 16 ) in normal mode and ( baud rate * 8 ) in fast mode. 

-> Whenever a start bit is detected, the receiver sees it, waits for 8 clocks(in normal mode) and then samples the bit again, if it is still low, it means it is really a start bit and if it is high, the system treats it as noise. 

-> If the start bit is validated then the consequent data bits are sampled for every 16 sample clocks. Which means it lands right in between of duration of each bit, the hardware is designed as such because the noise is minimal at the middle of the bit and sampling that is the safest. 

-> The Start bit is the syncing bit, and so is the stop. They are the ones which tie everything together properly. 

-> Since we are implementing UART, we don't need to look at the synchronous operation modes of the USART or the clock lines. Just Rx and the Tx lines are gonna be focused on.

a) selecting the mode of operation - Asynchronous. 
b) Configuring the frame to 8N1. (8 data bits, no parity and 1 stop bit.
c) Configuring the baud rate by adjusting the UBBRn registers. 
d) Enable the reciever. 

2) void setup() function which calls the USART setup and configure the leds. 

#) Multi run code: 
1) The void loop() which will read the USART reciever and set the LEDs accordingly. 
2) The usart_read() function reads the reciever data register and returns it.
